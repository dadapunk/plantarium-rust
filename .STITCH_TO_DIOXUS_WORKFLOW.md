## Why This Matters

Your Garden Cards vs Maintenance Panel problem happened because:
1. `grid-template-columns: 12` (INVALID SYNTAX) ❌
2. Display context wasn't explicit → grid vs flex ambiguous ❌
3. Width declarations missing → 100% meant different things ❌

The skill validates all 5 dimensions to prevent this.

## The 5 Validation Dimensions

| Dimension | Why | Example |
|-----------|-----|---------|
| **Display Contexts** | Parent/child relationships matter | Garden cards (grid) vs Recent Harvests (flex) |
| **Width/Height** | Always explicit, never assumed | `width: 100%` must be declared |
| **Media Queries** | All breakpoints, all properties | When grid changes cols, update gap too |
| **Flex/Grid Props** | Gap, alignment, wrap behavior | `gap: 2rem` is NOT optional |
| **No Conflicts** | `flex: 1` + `width: 300px` = race condition | One source of truth per dimension |

## Common Pattern

Every time you port Stitch CSS, check:
```
BEFORE (Stitch): .gardens-cards-grid { grid-template-columns: 1fr; }
AFTER (Port): .gardens-cards-grid { 
  display: grid; 
  grid-template-columns: 1fr; 
  width: 100%;
  gap: var(--spacing-8);
}
```

The difference:
- `display` is now EXPLICIT (was implicit)
- `width` is now EXPLICIT (was assumed)
- `gap` is now EXPLICIT (was hidden in Stitch CSS)

## Root Cause Learning

The skill documents why each pitfall happens, not just what to fix.

Example: **Pitfall 1 - Grid Columns vs Flex Width**
- Symptom: Cards at different widths
- Root: Child grid (2 cols) vs sibling flex (100%)
- Fix: Both must inherit from same `width: 100%` parent
