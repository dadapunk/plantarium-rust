## Quick Start

### 1. Start your Dioxus app (in one terminal)
```bash
cd ~/Code/plantarium-rust
cargo run --features desktop
```

This will run your app on `localhost:8080` (or the configured port).

### 2. Invoke the validation skill (in OpenCode)
```
/validate-layout
```

### 3. Provide parameters
```
URL: http://localhost:8080
Focus: widths (or alignment, display-context, all)
Breakpoints: (use defaults: 375×812, 768×1024, 1280×1024)
```

### 4. Receive analysis
- ✅ Accessibility snapshots at 3 breakpoints
- ✅ Visual screenshots for comparison
- ✅ CSS analysis (display contexts, widths, media queries)
- ✅ Specific recommendations

## What It Does

**For Plantarium Dashboard Validation:**

```
Checks if:
✅ Garden Cards (grid 2-col) has same width as Recent Harvests (flex)
✅ Maintenance Panel appears beside Garden Cards on desktop
✅ Display contexts are explicit at every level
✅ Media queries update ALL properties (not just one)
✅ Responsive behavior at all breakpoints

Outputs:
📸 Screenshots at 375px (mobile), 768px (tablet), 1280px (desktop)
📋 DOM structure (accessibility snapshots)
🔍 CSS analysis (what's missing, what's wrong)
💡 Specific fixes recommended
```

## Common Issues It Detects

### Issue: Garden Cards Narrower Than Recent Harvests
**What you see:** Different widths for sibling components
**What it reports:** Width mismatch between grid (2-col) and flex containers
**Fix:** Add `width: 100%` to both selectors

### Issue: Sidebar Below Instead of Beside Cards
**What you see:** Maintenance panel under content on desktop
**What it reports:** Missing `display: flex` context on parent
**Fix:** Add `display: flex; flex-direction: column` to `.dashboard-grid-main`

### Issue: Spacing Changes Only at One Breakpoint Property
**What you see:** Gap/padding looks wrong at tablet/mobile
**What it reports:** Incomplete media query (only some properties updated)
**Fix:** Update ALL related properties in media query, not just `grid-template-columns`

## Technical Details

### Playwright MCP Features Used
- `browser_navigate` - Open localhost:8080
- `browser_resize` - Change viewport (375, 768, 1280)
- `browser_snapshot` - Accessibility tree (CSS computed values)
- `browser_take_screenshot` - Visual PNG (for your Claude Vision)
- `browser_run_code` - Optional custom assertions

### Your Claude Vision
- Analyzes screenshots visually
- Detects layout problems automatically
- Suggests specific CSS fixes
- No special Vision API key needed (included in subscription)

### Efficiency
- **Snapshots:** ~200 tokens (structured JSON)
- **Screenshots:** ~150 tokens per image (Vision API)
- **Analysis:** ~150 tokens
- **Total per iteration:** 500-700 tokens
- **Cost:** ~$0.10-0.15 per validation

## Configuration Details

### Location: `~/.config/opencode/opencode.json`

```json
"playwright": {
  "type": "local",
  "command": ["npx", "@playwright/mcp@latest"],
  "args": [
    "--headless",           // No visible browser (faster)
    "--browser=chromium",   // Chromium engine only
    "--viewport-size=1280x1024",  // Default viewport
    "--output-dir=/tmp/playwright-output"  // Save outputs
  ],
  "enabled": true
}
```

### What Each Arg Does
- `--headless` - Runs without GUI (faster, no display needed)
- `--browser=chromium` - Uses Chrome/Chromium engine
- `--viewport-size` - Initial viewport (can be overridden)
- `--output-dir` - Where to save screenshots/traces

## Troubleshooting

### "Connection refused to http://localhost:8080"
```bash
# 1. Verify your app is running:
ps aux | grep cargo

# 2. Check if port is correct:
netstat -an | grep 8080

# 3. Start your app if not running:
cargo run --features desktop

# 4. Wait a few seconds for app to fully load before running skill
```

### "Playwright MCP not found"
```bash
# The skill uses NPX to download Playwright MCP on-demand
# If npx is not in PATH:
which npx

# If not found, install Node.js 18+:
node --version  # should be >= v18
```

### Screenshots are blank
```bash
# Possible causes:
# 1. App loading takes too long - wait longer before running skill
# 2. App renders in shadow DOM - Playwright may not capture
# 3. Port is different - adjust URL in skill

# Solution: Increase timeout in Playwright MCP args:
# Contact if this becomes an issue
```
